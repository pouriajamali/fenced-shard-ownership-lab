# v0.1.0-preview.1 — Fenced Shard Ownership Lab

Initial independent, synthetic single-shard lab: acquired-key fencing, atomic PostgreSQL high-water/effect/receipt state, cross-generation business idempotency and explicit uncertain outcomes. Native Windows/Linux self-contained CLI packages include user docs, source-revision manifests, notices and actual shipped-dependency SPDX SBOMs. Separately fetched Linux server fixtures are pinned references, not bundled servers.

The demo exercises 15 named cases including real three-member coordination, interrupted owned workers, quorum loss, sink process restart and an independent SQL-history oracle. Source/unit, native package execution and service integration receipts are separate evidence; CI/package/download receipts record exact commits and actual platforms. No benchmark, production HA, external rollback recovery, live order/market/account or profitability claim.

Artifacts are preview software. Source/tag/checksum signing establishes provenance under the pinned public key; it is not Windows Authenticode, exchange certification or exclusive ownership. Existing portfolio projects and private/shared systems are unchanged.

Pre-release hardening includes full pinned Npgsql/Microsoft.Extensions license texts and original per-component copyrights, fail-closed notice mapping, and canonical single-ed25519-key verification. Delivery checks use explicit exceptions so Python optimization cannot remove fingerprint, hash or package validation. Real signed-fixture and disposable-attacker regression cases cover multi-key/principal/comment injection and tampered archives in normal, -O and PYTHONOPTIMIZE modes. Superseded local candidates were retained for review and never released as binaries.
